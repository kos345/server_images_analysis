# Открытые вопросы (после уточнений)

Большинство ключевых параметров для MVP уже определены. Ниже — вопросы, которые **всё ещё влияют на реализацию** и требуют отдельного уточнения.

## 1) “Кейс” и изоляция в Neo4j (отдельные базы)

Вы обозначили: **каждый кейс изолирован**, cross-case correlation не нужен, но к данным кейса нужно возвращаться → **отдельные базы Neo4j на кейс**.

Открыто:

- **Что такое “кейс” в терминах входа**: один образ = один кейс, или кейс может включать несколько образов/запусков?
- **Как создаем/выбираем БД**:
  - система сама создает новую БД (например, `case_<case_id>`), или БД создается заранее и передается параметром?
- **Какая редакция Neo4j используется**:
  - Neo4j Community обычно не поддерживает multiple databases (в классическом режиме),
  - Neo4j Enterprise поддерживает multiple databases.

Чтобы корректно реализовать “отдельная БД на кейс”, нужно уточнить: **Community или Enterprise** (или допускается “отдельный контейнер Neo4j на кейс” как workaround).

## 2) Отчет (содержание)

Вы обозначили: отчет **в свободной форме**, но должен иметь **определенное содержание**, которое вы дадите позже.

Открыто:

- какой минимальный обязательный набор разделов/таблиц/полей должен быть в `report.md` и `report.json` (если `report.json` тоже должен меняться);
- нужно ли включать в отчет:
  - список всех пользователей / только “активных/подозрительных”,
  - полный перечень найденных файлов / только suspicious,
  - выдержки из логов (строки) или только агрегаты.

## 3) Полный рекурсивный обход ФС (практические ограничения)

Вы разрешили полный file-walk (в пределах образов ~20GB, до 1 часа).

Открыто:

- нужно ли **исключать** из полного обхода тяжелые каталоги по умолчанию (например, `/var/lib/docker`, большие базы, логи), или проходить всё без исключений;
- лимиты на чтение/хеширование:
  - хешировать все файлы или только исполняемые/подозрительные/из “опасных” директорий.
