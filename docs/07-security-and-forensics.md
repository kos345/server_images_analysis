# Безопасность и форензика (политики, ограничения, риски)

## 1) Read-only и изоляция

Обязательные правила:

- образ никогда не модифицируется;
- доступ к файловой системе образа — только read-only mount;
- запрещено выполнять любые бинарники/скрипты из образа;
- запрещено “boot” образа (нет QEMU run анализируемой ОС).

## 2) Обращение с секретами и приватными данными

В артефактах могут быть:

- приватные ключи,
- токены,
- пароли/хеши,
- персональные данные.

Политика MVP:

- приватные ключи не включать в отчет; допускается только fingerprint/метаданные;
- хеши паролей (`/etc/shadow`) не выводить полностью (по умолчанию) — либо маскировать;
- raw артефакты сохранять в `triage/<run>/raw`, но предусмотреть режим “redact”.

## 3) Сетевые обращения

По умолчанию сеть нужна только для:

- ipinfo enrichment (bulk).

Опции:

- `--ipinfo-enabled false` — полностью offline.

## 4) Исполняемые проверки malware

В MVP запрещаем:

- запуск подозрительных файлов из образа,
- отправку файлов во внешние сервисы без явного решения пользователя.

Разрешаем:

- расчет хеша,
- локальные сигнатурные проверки (если есть локальная база).

## 5) Audit trail

Система должна логировать:

- какие команды/инструменты запускались (qemu-img, guestmount и т.п.),
- какие файлы читались/копировались,
- где лежат результаты.

Audit должен помогать воспроизвести анализ и защищать от “галлюцинаций” LLM.
