# Архитектура решения (LangGraph + Neo4j GraphRAG)

## 1) Выбранный стиль: мультиагентный workflow-граф

Решение проектируется как **workflow-граф (LangGraph)**, где узлы — “агенты/исполнители” и системные шаги (ingest, triage, лог-парсинг, enrichment, KG-ingest, GraphRAG, report).  
Это дает:

- управляемую оркестрацию (ветвления, retries, чекпоинты),
- изоляцию обязанностей,
- воспроизводимость (фиксируем входы/выходы каждого шага),
- возможность расширения (добавлять новые агенты без переписывания всего пайплайна).

## 2) Компоненты

### 2.1 Оркестратор (Orchestrator Agent)

**Ответственность**
- принимает запрос анализа (`image_path`, параметры),
- формирует план выполнения (набор шагов),
- запускает узлы графа, агрегирует результаты,
- принимает решения о продолжении/остановке (например, “не Linux” → stop),
- отправляет нормализованные сущности в KG writer.

**Важно**: оркестратор **не** парсит файлы и логи сам — он дирижирует исполнителями.

### 2.2 Агент triage файловой системы (Filesystem Triage Agent)

**Ответственность**
- извлекает артефакты из образа Linux (read-only),
- нормализует в структурированные сущности (`User`, `Service`, `File`, …),
- дает “suspicion hints” (эвристики подозрительности) на уровне артефактов.

### 2.3 Агент анализа логов (Log Agent, MVP: SSH auth)

**Ответственность**
- парсит `auth.log`/`secure` (успешные SSH логины),
- коррелирует события с пользователями/IP из triage,
- отдает нормализованные `SSHLoginEvent` + связи.

### 2.4 Обогащение IP (Enrichment Agent / Tool)

**Ответственность**
- выделяет публичные IP,
- отправляет bulk-запрос в ipinfo,
- нормализует `IP`/`Geo`/`ASN` сущности и связи.

### 2.5 KG Writer (Neo4j Ingestor)

**Ответственность**
- upsert сущностей/отношений в Neo4j,
- ведет provenance (из какого артефакта и какого run получены данные),
- обеспечивает идемпотентность (повторный запуск не плодит дубликаты).

### 2.6 Analyst Agent (GraphRAG)

**Ответственность**
- выполняет retrieval из Neo4j (структурный + векторный),
- выявляет подозрительные связи и паттерны,
- формирует выводы и IoC.

### 2.7 Report Agent

**Ответственность**
- компоновка финального отчета (Markdown/JSON),
- ссылки на артефакты и subgraph evidence.

## 3) Взаимодействие компонентов: “State-first”

### 3.1 Почему “state-first”, а не REST как основной способ

Основной обмен — через **структурированный state** внутри LangGraph:

- меньше сетевых накладных расходов в MVP,
- проще трассировать, тестировать и воспроизводить,
- единый “источник правды” во время выполнения,
- REST можно добавить как “внешнюю оболочку” (submit job/status/results).

REST/queue (опционально) описаны в `docs/06-api-cli.md`.

### 3.2 Состояние выполнения (Run State) — ключевые поля

Состояние — JSON/Pydantic-модель, сохраняемая в `triage/<run>/state.json`:

- **run_id**: uuid
- **image**: пути, метаданные, формат, хеши
- **os**: family/distro/version/arch
- **mount**: способы доступа к ФС (guestmount/nbd), точки монтирования
- **artifacts_index**: список созданных файлов артефактов
- **entities/relations**: агрегированные нормализованные сущности
- **iocs**: агрегированные IoC
- **errors/warnings**: журнал проблем
- **neo4j**: статистика ingestion (nodes/edges)
- **report_paths**: пути к отчету

Подробные контракты — `docs/03-workflows-triage.md` и `docs/02-data-model-neo4j.md`.

## 4) LangGraph: узлы и переходы

### 4.1 Узлы (nodes)

- `ingest_image`
- `detect_os`
- `init_triage_dir`
- `fs_triage_agent`
- `log_agent_auth_ssh`
- `ip_enrichment`
- `kg_upsert`
- `graph_rag_analyst`
- `render_report`

### 4.2 Условия (guards)

- `if os.family != "linux" -> stop`
- `if no auth logs -> skip log_agent`
- `if no public IPs -> skip enrichment`

### 4.3 Ретраи/устойчивость

- внешние API (ipinfo): retries + backoff + кеширование по IP
- neo4j: reconnect/retry
- triage: “best-effort” — ошибка в одном артефакте не валит весь run (если не критично)

## 5) Инструменты (tools) и ограничения безопасности

Выполнение операций над образом — только через “tool layer”, который:

- гарантирует read-only,
- пишет полный audit (какая команда, когда, с какими параметрами),
- запрещает выполнение файлов из образа.

Список инструментов triage — в `docs/03-workflows-triage.md`.  
Ограничения форензики — `docs/07-security-and-forensics.md`.

## 6) Переиспользование готового набора инструментов `tools_src/`

В репозитории присутствует код `tools_src/`, который реализует требуемые детерминированные компоненты triage (pytsk3 collector, image processing, enrichment, HTML report).  
В рамках нашей архитектуры LangGraph:

- узлы графа вызывают методы классов из `tools_src/src/...`,
- LLM используется для summaries и аналитики (GraphRAG), но не для извлечения файлов/логов.

Подробная карта соответствия классов и узлов — `docs/05-tools-src-integration.md`.
