Общие требования:
- Проект разрабатывается на python 3.11
- Во всех модулях должно быть настроено логирование в файл (также логироваться должны обращения и ответы LLM)
- Функционал реализуется в формате классов
- Учти, что в дальнейшем инструментарий будет преобразован в инструменты AI-агента на базе GigaChat с использованием langchain, langgraph, langchain_gigachat
- Все api-ключи и другие данные авторизации должны браться из файла .env 

# Класс "ImageProcessor" для работы с файлом образа:
1. Класс проверяет тип файла с образом (является ли образ RAW-образом)
2. После проверки при необходимости с помощью инструмента qemu-img образ конвертируется в raw-формат 

# Класс "TriageCollector" для работы с файлом образа:
- Класс использует библиотеку pytsk3 для сбора артефактов.
- Класс читает конфиг triage.yaml с настройкой дополнительных артефактов (файлов и директорий) для сбора.
- Класс читает файл triage_prompts.py с промптами, использующимися для дополнительной обработки собранной информации.

1. Осуществляем проверку операционой системы внутри анализируемого образа
  - Если система не принадлежит семейству Linux, завершаем работу.
  - Если система принадлежит семейству Linux, то в директории проекта в случае отсутствия создается поддиректория "triage". Для сохранения дальнейших результатов анализа образа в поддиректории "triage" создается директория с названием, содержащим название файла образа, текущую дату и uuid.  

2. Осуществляется сбор артефактов в системе (проводит triage):
    - определяет операционную систему (информация сохраняется в файл triage/{созданная ранее директория образа}/system/OS.txt)
    - перечень пользователей из /etc/passwd (информация сохраняется в файл triage/{созданная ранее директория образа}/users/passwd.txt)
    - хеши паролей пользователей из /etc/shadow (информация сохраняется в файл triage/{созданная ранее директория образа}/users/shadow.txt)
    - история команд всех пользователей (информация сохраняется в файл triage/{созданная ранее директория образа}/users/history_{имя пользователя}.txt)
    - файловая структура в /home/ с максимальной глубиной поиска (информация сохраняется в файл triage/{созданная ранее директория образа}/files/home.txt)
    - файловая структура в /root/ с максимальной глубиной поиска (информация сохраняется в файл triage/{созданная ранее директория образа}/files/root.txt)
    - перечень файлов и директорий в корневой директории (информация сохраняется в файл triage/{созданная ранее директория образа}/files/root_dir.txt)
    - перечень системных сервисов (информация сохраняется в файл triage/{созданная ранее директория образа}/system/services.txt)
    - перечень запланированных задач  (информация сохраняется в файл triage/{созданная ранее директория образа}/system/cron.txt)
    - перечень установленных пакетов через пакетные менеджеры (информация сохраняется в файл triage/{созданная ранее директория образа}/system/apt.txt) 
    - перечень логов из директории /var/log (информация сохраняется в файл triage/{созданная ранее директория образа}/logs/var.txt) 
    - перечень логов из директории /var/www (информация сохраняется в файл triage/{созданная ранее директория образа}/logs/www.txt) 
    - информация о docker-образах в системе (информация сохраняется в файл triage/{созданная ранее директория образа}/system/docker.txt) 

3. Для перечня системных сервисов (из файла triage/{созданная ранее директория образа}/system/services.txt) с помощью обращения к LLM GigaChat с указанием промпта "system_services" из triage_prompts.py выделяем перечень нестандартных сервисов и сохраняем список в файл triage/{созданная ранее директория образа}/summaries/services_summary.md

4. Для перечня запланированных задач (из файла triage/{созданная ранее директория образа}/system/cron.txt) с помощью обращения к LLM GigaChat с указанием промпта "cron" из triage_prompts.py формируем описание задач и сохраняем в файл triage/{созданная ранее директория образа}/summaries/cron_summary.md

5. Для перечня установленных пакетов через пакетные менеджеры (из файла triage/{созданная ранее директория образа}/system/apt.txt) с помощью обращения к LLM GigaChat с указанием промпта "apt_summary" из triage_prompts.py формируем описание подозрительных пакетов и сохраняем в файл triage/{созданная ранее директория образа}/summaries/apt_summary.md

6. По перечню файлов логов из /var/www (файл triage/{созданная ранее директория образа}/logs/www.txt) и логов из директории /var/log (файл triage/{созданная ранее директория образа}/logs/var.txt) с помощью обращения к LLM GigaChat с указанием промпта "log_files_summary" из triage_prompts.py формируем описание имеющихся веб-серверов и специализированного ПО и сохраняем в файл triage/{созданная ранее директория образа}/summaries/log_files_summary.md

7. По перечню файлов и директорий в корневой директории (файл triage/{созданная ранее директория образа}/files/root_dir.txt) с помощью обращения к LLM GigaChat с указанием промпта "root_files_summary" из triage_prompts.py формируем список нестандартных (не системных) файлов и директорий и сохраняем в файл triage/{созданная ранее директория образа}/summaries/root_files_summary.md

8.  Для обнаруженных логов, список которых сохранен в файлах triage/{созданная ранее директория образа}/logs/var.txt и triage/{созданная ранее директория образа}/logs/www.txt извлекаем файлы из образа и сохраняем в директорию triage/{созданная ранее директория образа}/logs/raw в поддиректориях "var" и "www" соответственно

9. Для логов AUTH из triage/{созданная ранее директория образа}/logs/raw/var выполняем следующие действия:
   - Разархивируем (если лог хранится в сжатом виде) 
   - Объединяем все AUTH-журналы в один файл triage/{созданная ранее директория образа}/logs/clear/auth_full.log
   - Парсим логи из файла triage/{созданная ранее директория образа}/logs/clear/auth_full.log и ищем только успешные входы по SSH. Найденные строки сохраняем в файл triage/{созданная ранее директория образа}/logs/clear/success_auth.log
   - Из файла triage/{созданная ранее директория образа}/logs/clear/success_auth.log с помощью регулярных выражений извлекаем публичные IP-адреса и с помощью обращения к API сервиса ip.info (bulk-запрос) обогащаем информацию по ip-адресам (обращение к API должно быть через объект класса ContextEnricher). Полученную информацию сохраняем в файл triage/{созданная ранее директория образа}/logs/clear/success_auth_IP.json

10. Для файлов с историей команд из triage/{созданная ранее директория образа}/users/history_{имя пользователя}.txt выполняем следующие действия:
   - Удаляем дублирующиеся строки и сохраняем обновленные файлы в triage/{созданная ранее директория образа}/users/history_clear_{имя пользователя}.txt
   - Из файлов triage/{созданная ранее директория образа}/users/history_clear_{имя пользователя}.txt с помощью регулярных выражений извлекаем публичные IP-адреса и с помощью обращения к API сервиса ip.info (bulk-запрос) обогащаем информацию по ip-адресам (обращение к API должно быть через объект класса ContextEnricher). Полученную информацию сохраняем в файл triage/{созданная ранее директория образа}/users/history_clear_{имя пользователя}_IP.json
   - С помощью обращения к LLM GigaChat с указанием промпта "history_summary" из triage_prompts.py формируем summary по файлам triage/{созданная ранее директория образа}/users/history_clear_{имя пользователя}.txt и сохраняем сформированные саммари в файлы triage/{созданная ранее директория образа}/summaries/history_{имя пользователя}_summary.md

11.  Для файлов, список которых сохранен в файлах  triage/{созданная ранее директория образа}/files/home.txt и triage/{созданная ранее директория образа}/files/root.txt выполняем следующие действия:
   - Извлекаем файлы из образа и сохраняем в директорию triage/{созданная ранее директория образа}/files/raw
   - С помощью обращения к LLM GigaChat с указанием промпта "history_summary" из triage_prompts.py формируем summary по файлам и сохраняем сформированные саммари в файлы triage/{созданная ранее директория образа}/summaries/home_files_summary.md

12. Для файлов из triage/{созданная ранее директория образа}/files/raw определяем:
    - имя файла    
    - тип файла
	- расположение на сервере
    - timestamp создания
    - timestamp последнего редактирования
    - хеш-сумму MD5 
    - хеш-сумму SHA1
    - хеш-сумму SHA256
  Данные укладываем в JSON-файл triage/{созданная ранее директория образа}/files/iocs_full.json 

13. С помощью обращения к LLM GigaChat с указанием промпта "files_wl" из triage_prompts.py определяем лишние файлы и удаляем их из JSON. Обновленный JSON сохраняем в triage/{созданная ранее директория образа}/files/iocs_clear.json 

14. Для каждого файла из JSON triage/{созданная ранее директория образа}/files/iocs_clear.json берем хеш-сумму SHA256 и с помощью обращения к API VirusTotal получаем информацию по файлу (обращение к API должно быть через объект класса ContextEnricher). Полученную информацию добавляем в JSON в поле "VT". Обновленный JSON сохраняем в triage/{созданная ранее директория образа}/files/iocs_vt.json

# Класс "ReportGenerator" для формирования результатов анализа в формате HTML-документа и краткого сообщения для Telegram
1. Отчет формируется с помощью шаблонизатора jinja. HTML-файл с шаблоном должен храниться в папке templates (в корне проекта). Что должно входить в отчет:
    - Общие собранные сведения о системе из файлов:
		- Версия ОС (из файла triage/{созданная ранее директория образа}/system/OS.txt)
		- Данные о пользователях: (из файлов triage/{созданная ранее директория образа}/users/passwd.txt и triage/{созданная ранее директория образа}/users/shadow.txt)
		- Перечень нестандартных системных сервисов (из файла triage/{созданная ранее директория образа}/summaries/services_summary.md)
		- Перечень запланированных задач (из файла triage/{созданная ранее директория образа}/summaries/cron_summary.md)
		- Перечень подозрительных пакетов (из файла triage/{созданная ранее директория образа}/summaries/apt_summary.md)
		- Перечень веб-серверов и специализированного ПО (из файла triage/{созданная ранее директория образа}/summaries/log_files_summary.md)
		- Информация о docker-образах в системе (из файла triage/{созданная ранее директория образа}/system/docker.txt) 

	- Информация о файлах:
		- Нестандартные директории и файлы в корневой директории (из файла triage/{созданная ранее директория образа}/summaries/root_files_summary.md)
		- Файловая структура в /home/ (из файла triage/{созданная ранее директория образа}/files/home.txt)
		- Файловая структура в /root/ (из файла triage/{созданная ранее директория образа}/files/root.txt)
		- Нестандартные директории и файлы в директориях пользователей (из файла triage/{созданная ранее директория образа}/summaries/home_files_summary.md)

	- Информация о подключениях к системе (из файла triage/{созданная ранее директория образа}/logs/clear/success_auth.log)
	- Обогащенная информация по IP-адресам (из файла triage/{созданная ранее директория образа}/logs/clear/success_auth_IP.json)
	 
	- Данные об активности каждого пользователя:
		- История команд (из файла triage/{созданная ранее директория образа}/users/history_clear_{имя пользователя}.txt)
		- Общая сводка по командам пользователя из файла (triage/{созданная ранее директория образа}/summaries/history_{имя пользователя}_summary.md)
	
	- Индикаторы компрометации:
		- IP-адреса из истории команд (из файлов triage/{созданная ранее директория образа}/users/history_clear_{имя пользователя}_IP.json)
		- Хостовые артефакты (из файла triage/{созданная ранее директория образа}/files/iocs_full.json)
