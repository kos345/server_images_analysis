Мне необходимо разработать AI-агента или мультиагентную сеть по анализу образов серверов на предмет использование данного сервера кибер преступниками для своих противоправных действий (атаки на инфраструктуру, разведка, сбор данных, фишинг и тд).
 Агенту приходят образы серверов, которые предположительно могли быть использованы злоумышленниками для проведения своих грязных дел.

Требуется изучить образ на предмет следов деятельности злоумышленников: пользователи, история команд, логи, хеши паролей, подозрительные файлы и тд

Цель: понять, использовался ли данный сервер в операциях злоумышленников, собрать информацию об используемых методах и функционале злоумышленников.

Четкого описания и детальных шагов нет, так как это глубоко индивидуальный процесс, требующий глубокого экспертного подхода.

# Верхнеуровнево процесс выглядит так:

   1) При необходимости с помощью инструмента qemu-img образ конвертируется в raw-формат 
   2) Осуществляем проверку операционой системы внутри анализируемого образа
      - Если система не принадлежит семейству Linux, завершаем работу.
      - Если система принадлежит семейству Linux, то в директории проекта в случае отсутствия создается поддиректория "triage". Для сохранения дальнейших результатов анализа образа в поддиректории "triage" создается директория с названием, содержащим название файла образа, текущую дату и uuid
   3) Осуществляется сбор артефактов в системе (проводит triage)
    Проводим анализ:
        - обираем данные об ОС, конфигурации сети
        - Собираем данные о пользователях, истории команд пользователей
        - Выделяем перечень нестандартных сервисов
        - Формируем описание подозрительных пакетов
        - ДАнные планировщика задач
        - Формируем описание имеющихся веб-серверов и специализированного ПО
        - ДАнные об установленных докер контейнерах
        - Формируем список нестандартных (не системных) файлов и директорий
    По всем артефактам собираем саммари, какие есть наестандартные вещи, подозрительные в части совершения действий хакеров
    Далее анализируем логи
        Ищем только успешные входы по SSH
        Извлекаем публичные IP-адреса и с помощью обращения к API сервиса ip.info (bulk-запрос) обогащаем информацию по ip-адресам
     Проверяем нестандартные файлы на предмет вирусов и тд
 4) Составляем отчет:
        Общие собранные сведения о системе из файлов
        Информация о файлах
        Информация о подключениях к системе
        Обогащенная информация по IP-адресам
        Данные об активности каждого пользователя
        Индикаторы компрометации.

Я представляю следующую архитектуру.
Есть агент оркестретор, который планирует действия и распределяет задачи между другими агентами. 
Есть агенты-исполнители: 
1) агент, анализирующий файловую систему;
2) агент, анализирующий логи. Для mvp нализируем только AUTH лог ssh. И изем только те записи, в которых встречается информация из проанализированной ранее файловой системе (ip  адреса, пользователи и тд)
Эти агенты отдают все подозрительные артефакты агенту-оркестратор, который заносит все данный в графовую базу знаний. Очень важно понимать взаимосвязи между разными артефактами. Поэтому используем графовую базу знаений.
3) ДАлее агент анализатор - смотрит в графовую базу знаний и ищет подозрительные вещи, связи  и создает саммари отчет.

Помоги создать спецификацию, котоую будет использовать будет использовать LLM для составления плана разработки и далее для самой разработки.
